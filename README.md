## 结构

- `SKILL.md` — Agent 技能文件：选用规则与维护流程（根目录，先读它）
- `prompts.json` — 全库机器可读数据（空间和 Skill 的数据源）：id、标题、分类、风格标签、场景、英文提示词（复制用）、中文说明、适用工具、预览与验证字段
- `prompts/<分类>.md` — 按分类的人读版，已验证条目内嵌展示 GIF
- `favorites.json` — 收藏清单（id 数组）。**选设计时收藏优先**
- `inbox.md` — 收集待整理区：新收集先落这里（标来源和日期），整理去重后才进正式库
- `previews/<id>.png` / `previews/<id>.gif` — 已验证条目的生成效果图与展示 GIF

## 怎么用

1. 做 UI 设计时，先按场景/分类找候选，再按风格标签匹配；收藏的排最前，已验证的优先于未验证的。细则见 `SKILL.md`。
2. 每条的英文提示词可直接复制到 v0 / Lovable / Cursor 等工具生成界面；中文说明帮你快速判断长什么样。
3. 带 ✅ verified 标记的条目是已按提示词实际生成并目检通过的，效果以 `previews/` 里的 GIF 为准。

## 维护规则

1. 新增提示词必须有：唯一 id（英文短横线）、分类、至少 1 个风格标签、场景、英文提示词、中文说明、适用工具。
2. 入库前查 `prompts.json` 去重：同一场景+同一风格只保留一条，变体在原条目里注明。
3. **生成验证**：收集的提示词入库后必须实际生成一次并目检，通过才标 `verified`，效果图和展示 GIF 存 `previews/`；不通过就改提示词或如实记录差距，不假标。
4. 收藏只增删 `favorites.json`，不动提示词正文。
5. 每次改库都 git commit（信息写清动作和条目），并同步更新本 README 的状态与统计。
